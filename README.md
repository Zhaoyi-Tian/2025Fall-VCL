## 实现结果

![image-20260114215655935](/images/image-20260114215655935.png)

- 可通过**文件导入**和**文本输入**来输入文本，通过python脚本对文本进行清洗和**jieba**分词后通过**TF-IDF**算法得到权重，权重通过**对数平滑映射**得到词云字体大小，通过映射到 HSL 色彩空间中的**色相**上，从而形成从冷色调（低权重）到暖色调（高权重）的过渡。

- 在**词云的交互**上，我实现了和论文演示一样的Gizmo交互，**移动、旋转、缩放三合一**。用户不仅可以调整位置，还可以直观地旋转词语以适应布局缝隙，或者实时缩放词语大小以强调特定内容，所有这些操作都会立即触发布局的物理自适应调整。

- **生成词云**时为了给物理模拟一个比较好的初值，我实现了一个贪心的螺旋线放置算法。将词语按权重排序，依次放置。对于每个新词，从画布中心沿**阿基米德螺旋线**向外搜索，直到找到第一个不与已放置词语碰撞且（如果启用蒙版）完全位于蒙版内的位置。为了密度，我进行了一些优化：

  - **均匀采样**：在无蒙版时简单的线性增加 𝜃，会导致外圈采样点稀疏。在蒙版模式下，我改为基于弧长的步进策略，确保无论在靠近中心还是远离中心的地方，搜索密度都是一致的，这对于填满形状的不规则边缘至关重要。
  - **重叠松弛 (Relaxed Collision)**：在初始布局检测碰撞时，特意允许 10% 的包围盒重叠（boxHalfSize * 0.9）。这是一种“过填充”策略，允许小词稍微挤入大词的缝隙中，随后依赖物理引擎的排斥力将它们自然推开，从而获得比严格不重叠更紧凑的最终效果。

- 在**布局与模拟**中可以启用**物理模拟**，以实现对词云的编辑：

  - 我采用了自主实现的基于脉冲的刚体动力学求解器，参考论文[ErinCatto_IterativeDynamics_GDC2005.pdf](https://box2d.org/files/ErinCatto_IterativeDynamics_GDC2005.pdf)和Box2D Lite 核心逻辑实现了一个**轻量级的 2D 物理引擎**。采用 Sequential Impulse 方法求解速度约束，支持 Warm Starting (热启动) 利用上一帧的积累脉冲加速收敛，并引入 Baumgarte Stabilization 修正位置穿透，在 20 次迭代下提高了堆叠稳定性。

  - 词云的碰撞由论文中的词级和字符级包围盒判断，即下图中的(c)。对于英文大词（大于最大词的50%），采用(c)的碰撞框，英文小词和中文词采用(a)的碰撞框。

    <img src="/images/image-20260114212756091.png" alt="image-20260114212756091" style="zoom: 67%;" />

  - 为简单起见，我固定角动量变化，提供了**全局角度锁定**这一调整所有词角度的滑条。

- 在**外观与蒙版**中，可以调整**背景**颜色和透明度并保存为png图片，可以切换字体。并且我加上了一个简单的**犹他茶壶**作为蒙版：

  - **SDF (Signed Distance Field) 驱动的精确交互**
    为了支持非凸、任意复杂形状的蒙版（如茶壶、兔子），我没有使用简单的二值化碰撞，而是实现了基于 SDF (有向距离场) 的交互系统。
  - **生成**：加载图片后，计算每个像素到最近边界的距离。内部为负值，外部为正值。
    **检测**：在物理模拟中，对词语 OBB 的 9 个关键点（角点+中心+边中点）进行 SDF 采样，若 distance > 0 则判定为出界。
    **响应**：利用 SDF 的数值梯度直接获得碰撞法线，将其转化为刚体接触约束（Contact Constraint），纳入 Impulse Solver 统一求解，实现了平滑的边界反弹效果。

  - **基于可见性的引力约束(Visibility-based Attraction Constraint)**
    在 EdWordle 的中心引力模型中加入了一个改进：路径遮挡检测。
    如果一个词想被拉向中心，但路径上经过了 Mask 的“无效区域”（例如甜甜圈的空洞、字母C的开口），则屏蔽该引力。这防止了词语穿过形状的镂空部分直线飞向中心，从而保持了 Mask 的拓扑结构。

## 实现难点

1. 字体渲染和旋转：
   1. 一开始复用 ImGui 的**字体图集纹理**（ImGui::GetIO().Fonts->TexID），逐字从 ImFont 获取 glyph 的 UV/advance，拼接为一串四边形，每个四边形在顶点着色器里应用旋转。但是直接糊成一团了。
   2. 改进为**FreeType + MSDF**，一开始渲染时周围会有竖线，在图集中字形之间增加 padding后竖线消失；为防止纹理线性插值形成的黑边，采用预乘 Alpha的方式；可在ui中切换字体，但需要加载一段时间。
2. 物理模拟和渲染的**解耦**

   - 一开始在**wsl2**上运行，把物理模拟放在OnRender中，虽然显示帧率为120fps，但是依旧非常卡，于是试图优化，先用多线程将渲染与物理的解耦，然后还是很卡，再用**双缓冲和原子指针**减少拷贝，避免锁竞争，但依旧没有解决问题。
   - 最后通过拖拽时发现鼠标更新不连续，大部分时间位置变化都是零后才意识到可能是**wslg**的问题，切换到windows平台后才解决问题。这个解耦的架构我也保留了下来，在关闭垂直同步的情况下渲染能跑到600fps往上
   - 现在好处就是帧率独立，我们可以固定并通过侧边栏调整物理模拟的帧率，保证模拟稳定性
3. 在模拟和渲染解耦情况下的交互
   - 在渲染和物理模拟的解耦的基础上，我采用了**只读输入 + 增量输出**模式，HandleWordGizmo() 读取只读快照判断用户点击了哪个词、在拖动还是旋转，然后计算增量（这帧鼠标移动了多少、旋转了多少度），而非绝对值，将增量通过命令队列发送给物理线程，物理线程在真实位置上累加增量。
   - 因为渲染的快照可能滞后1-2帧，所以必须采用增量更新，让物理线程直接累加，不能用快照位置计算绝对值，否则会出现拖不动的情况。
4. 物理模拟的稳定性和收敛
   - 基于脉冲的刚体动力学求解器的编写，一开始写的**显式欧拉稳定性**不高，后面参考**box-lite**写了半隐式欧拉并加上了Warm Starting才有了比较好的稳定性，但在有蒙版的时候还是可能出现词语之间相互挤压导致重叠，至今没有解决，临时的解决办法是将重叠的词云拖到剩余空间多的地方，自然会分开。
   - 论文中只是给出了公式，并没有给出各个参数的**量纲**，调试很久，加上很多修正才能调出一个感觉比较合理的参数。
